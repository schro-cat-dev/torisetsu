# ハーネス改善効果 実測履歴

## 目的

ハーネス改善の前後で、修正回数、所要時間、品質条件通過率がどう変わったかを履歴として残す。

## ファイル名

```text
YYYY-MM-DD-<target>-<change>.md
```

例:

```text
2026-08-25-todo-review-quality-harness.md
```

## 記録テンプレート

```text
対象:

比較する改善:

改善前:
- 修正依頼回数:
- 所要時間:
- 品質条件通過率:
- 人間レビュー追加検出数:

改善後:
- 修正依頼回数:
- 所要時間:
- 品質条件通過率:
- 人間レビュー追加検出数:

計算:
- 修正依頼回数の減少率:
- 所要時間の減少率:

解釈:

次に直すこと:
```

## 記録例

```text
対象:
TODOアプリレビュー

比較する改善:
HarnessにUI/状態/API/保存/a11yの品質条件を追加

改善前:
- 修正依頼回数: 5
- 所要時間: 180分
- 品質条件通過率: 未測定
- 人間レビュー追加検出数: 8

改善後:
- 修正依頼回数: 1
- 所要時間: 45分
- 品質条件通過率: 100%
- 人間レビュー追加検出数: 1

計算:
- 修正依頼回数の減少率: 80%
- 所要時間の減少率: 75%

解釈:
この1本だけでは断定しない。似た履歴が3本以上出たら、Harness改善が効いている可能性を強めに見る。
```

## 注意

- 改善前と改善後は、できるだけ同じ種類のタスクで比較する。
- タスク難易度が違う場合は、解釈に必ず書く。
- 品質条件100%通過でも、品質条件自体が薄い場合は改善扱いにしない。
