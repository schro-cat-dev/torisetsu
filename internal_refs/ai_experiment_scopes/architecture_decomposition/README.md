# AI内部アーキテクチャ仮説

## 目的

AIの内部そのものを断定せず、観測できる挙動から仮説として分解する。

## 扱うこと

- 入力: user message、system/developer rules、添付情報、repo内ファイル。
- 文脈: 過去会話、skill、AGENTS.md、既存ドキュメント。
- 推論: 目的理解、前提分解、作業手順、検証方法の選択。
- tool実行: shell、file edit、web、画像生成など。
- 出力: 回答、編集、ログ、commit、push。

## 記録する観点

| 観点 | 内容 | 例 |
|---|---|---|
| 入力 | 何を渡したか | README修正依頼、期限なし、push希望あり |
| 制約 | 何を守らせたか | READMEを勝手に上書きしない |
| 推論の癖 | どう動いたか | 先に調査しすぎる、またはすぐ実装する |
| 出力 | 何が出たか | docs追加、summary、commit |
| ズレ | 期待と違った点 | 仕様書の粒度が粗い |

## 具体例

```text
入力: TODOアプリを作ってほしい
制約: localStorageにTODO本体を置かない
観測: AIが最初にlocalStorageを候補に出した
推測: secure by designの優先度が入力で十分に固定されていなかった
次の改善: 保存方式を設計前提として明記する
```
