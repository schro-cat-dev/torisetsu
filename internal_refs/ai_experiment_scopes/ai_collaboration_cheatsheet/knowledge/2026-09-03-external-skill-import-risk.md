# 外部skill取り込み時の権利・セキュリティ判断

## 状況

公開されているagent skill / plugin / tool系repoを、torisetsuのskill移行元として見るか相談していた。

## AIが迷った点

外部repoに良さそうな構造や手順がある場合、どこまで参照し、どこから先を取り込み扱いにするか。

## ユーザーの返答

外部から勝手に取ってくると、権利の問題もセキュリティの問題も発生する。

## 次回の動き

- 外部repoは、原則としてそのままinstall / copy / vendoringしない。
- 参照する場合も、license、実行script、MCP、外部通信、secret入力、生成物の出どころを確認する。
- 取り込むのは文章や実装そのものではなく、必要な設計観点、失敗条件、検証観点だけにする。
- 自作できる小さなtoolは、外部依存よりローカル実装を優先する。
- READMEや動画でベンチマーク優位を強く押し出し、構成、再現手順、安全境界、失敗条件がぱっと読めないrepoは、姿勢として低評価にする。
- 自分たちで作ったベンチマークで自分たちの手法が一番良い、という主張は採用判断の強い根拠にしない。見るなら、外部ベンチ、第三者再現、公開データ、固定protocol、失敗例、負けた条件があるかを確認する。
