# Responsibility Support Agent

作成日: 2026-09-02

## 目的

連絡、判断、責任範囲の抜け漏れを減らすための支援エージェント案を残す。

ここで作りたいものは、本人の性格を変えるための道具ではない。

気合い、記憶力、まめさに依存しすぎず、最低限の連絡と判断を外部化して、事故を減らす仕組みにする。

## 解きたい課題

- 返信が必要な連絡を見落とす。
- 誰に何を返すべきかが頭の中に残り、整理されない。
- 判断が止まったまま時間が過ぎる。
- 自分が抱えるべきことと、他人へ渡すべきことが混ざる。
- 遅れた後の連絡が重くなり、さらに放置しやすくなる。
- 軽いToDoやリマインダーでは、本人の意志力に依存しすぎる。

## 方針

甘いリマインダーではなく、少し強制力のあるエージェントとして設計する。

重要なのは、ユーザーに「ちゃんと頑張って整理してもらう」ことではない。

ユーザーが整理できていない状態でも、エージェント側が未返信、未判断、期限、相手待ち、自分待ちを拾い、次の行動まで出す。

## 最初に作る範囲

MVPでは、外部サービス連携を急がない。まずは手入力または貼り付け入力で成立させる。

入力:

```text
気になっている連絡
相手
期限
今止まっている理由
自分で決めるべきか、誰かに確認すべきか
```

出力:

```text
今日返すべき順番
次に送る一文
放置するとまずい理由
誰に渡すべきか
期限を過ぎた場合の謝罪と状況共有文
```

## 必要な機能

| 機能 | 目的 | 厳しさ |
|---|---|---|
| 未返信一覧 | 返すべき相手を忘れない | 毎日表示する |
| 未判断一覧 | 決めていないことを埋もれさせない | 期限順に出す |
| 返信下書き | 連絡の心理的負荷を下げる | 1クリックで作る |
| 責任範囲整理 | 自分で抱えすぎない | 自分、相手待ち、上位確認に分ける |
| 放置時の再通知 | 見なかったことにしにくくする | 朝、夕方、期限前 |
| 遅延時の文面切替 | 遅れた後の再開を軽くする | 謝罪と状況共有を自動生成する |

## 避けること

- 人格評価アプリにしない。
- 「怠惰を直す」ことを目的にしない。
- 自由入力だけのToDoアプリにしない。
- 通知だけで終わらせない。
- ユーザーに毎回ゼロから優先順位を決めさせない。
- 連絡相手や内容を勝手に送信しない。

## 完了条件の例

- 朝に見れば、今日返すべき連絡が分かる。
- 各連絡に、次に送れる文面が1つ以上ある。
- 放置中、相手待ち、自分待ち、上位確認待ちが分かれている。
- 期限超過時は、通常返信ではなく遅延連絡の文面が出る。
- ユーザーが手で整理しなくても、最低限の事故候補が見える。

## 次に決めること

- 対象を個人利用にするか、チーム利用にするか。
- 入力元を手入力、チャット貼り付け、Slack、メールのどこから始めるか。
- 通知の強さをどこまで上げるか。
- エージェントが提案だけするのか、送信前の下書き作成までにするのか。
- 責任範囲の分類を、どのラベルで持つか。
