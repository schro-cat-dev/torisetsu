人間の業務を部分的にAIに委任する上で、その品質を保ち、作業スプリント（PDCA）をループさせ、走行ルールを設定し、アウトプットの質を高めるための AIのいわばレースルート設計である

# ハーネスの大枠アーキテクチャ

## 思考の流れ

AIを業務に導入したい → AIは何がどこまでできるのか → プロンプトを設計してこの作業フローのこのステップにおいて、こういうタスクをして欲しい時にはこのプロンプト群を依頼しよう（一つだけでは出力の質が担保されないため、多様性を持たせる（発火を何パターンか、優先順位をつけて渡す）） → 権限を渡しすぎると事故る → 権限制約を設定しよう → 出力の質はどう判定すればいいだろうか？ AIの言葉「できました」をどこまで信用するか → 人間のレビューはどの順序でどのくらいの量でどこを見ればいいか、実施すればいいか → 現時点で本当に効率化になっているか、レビューと修正が自分たちでするのよりコストが削減できているか → 改善が必要な場合にはフィードバックをどこかで日時・バージョンベースで管理したい → フィードバックを受けて全く同じ入力で修正後で検証する

## 確認したい前提

- 外部APIやAIモデルに依存する場合、そのバージョンおよびその時点でのバージョンに紐づけられた内部的な学習セット、割り当てリソース、動作パラメータ（推論の多様性など）により **性能が左右される**

- AIのモデルに応じて内部アーキテクチャが異なる → 依頼するプロンプトおよびアウトプットのパターンを適切に把握し、**どうしたらこのモデルのバージョンに対して最適な入力をし、推論のためのベクトルづけをできるか** を軸の1つにおき、常にできているかをチェックする

- SNSなどで公表されている真偽の定かではない情報は信用せず、その日時・モデル・バージョンなどの情報もメタ情報として付与しつつ、**一定水準以上の再現性を持った実物の動作のみをデータとして信用する**

- AIが sandbox を抜け出して勝手に連絡してきた、などの誇張表現、マーケティング表現を真に受けず、流されない（することをする、軸をぶらさない）

## アーキテクチャ

業務上の目的/KPI（AIにより半自動化したい作業スコープ） → AIの性能・挙動仕様の把握 → 依頼タスク、プロンプトのフロー全体・個別の詳細設計 → AIモデルに依頼（コンテキスト情報、ツール実行環境（隔離性、安全性の事前確認）を渡す） → アウトプットの検証作業（事前に検証方法をそのまま実行すれば100%確認できるようにしておく） → 他作業との合流前チェック（パターンマッチなどチェック項目確認） → 他タスクとの合流または次ステップに進める → 最終アウトプットの確認、良い点・悪い点の洗い出し → AI自体にその良い点悪い点がここまでのフローでどこにあったかを特定・報告させる + 自分自身でも**キーワードベースで確認**し、改善点を考える → 改善し、動作させる

def filter_and_post_reviews(ai_result_json: dict, diff_info: dict):
    valid_comments = []
    
    for review in ai_result_json["reviews"]:
        # 1. 閾値フィルタ: 自信が80%以下のフワッとした指摘は捨てる
        if review["confidence"] < 0.8:
            continue
            
        # 2. Diff整合性フィルタ: 変更されていない行への指摘はGitHub APIでエラーになるため捨てる
        if review["line"] not in diff_info["changed_lines"].get(review["file"], []):
            continue
            
        # 3. 深刻度フィルタ: 些細な指摘(LOW)はPRをノイズで埋めるため無視
        if review["severity"] == "LOW":
            continue
            
        valid_comments.append(review)

    # 4. 上限フィルタ: コメントが多すぎると開発者が萎えるため、上位5件に絞る
    valid_comments = sorted(valid_comments, key=lambda x: x["confidence"], reverse=True)[:5]
    
    # 最後にGitHub APIを叩く (いきなりRequest Changesではなく、最初はCommentとして)
    post_to_github(valid_comments, action="COMMENT")

```
