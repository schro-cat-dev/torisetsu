# Structured Discussion Rules

ここは、難しい話を小さく分けて議論するためのルールを、後から少しずつ追加する場所。

## 構造化の基本ルール

- 大きい話は、ただ小さく分けるだけで終わらせない。まず `何のために分けるか` を置く。
- 次に、`目的`、`前提`、`事実`、`観察`、`解釈`、`推測`、`関係`、`決めること` に分ける。
- 分けた要素は、互いにどう影響するかを見る。例: `前提が変わると結論が変わる`、`観察が弱いと推測が増える`。
- 作業中にズレを感じたら、要素の分け方か関係の置き方を見直す。
- まだ細かい型は固定しない。会話しながら、使いやすい形に育てる。

## 事実と解釈の分け方

- 作業や調査では、まず情報を `物理・実体の動き`、`観察されたこと`、`解釈`、`推測` に分ける。
- それぞれの混ざり具合は、初期値として比率で見る。例: `観察 70% / 解釈 20% / 推測 10%`。
- 比率判断にユーザーから修正が入った場合は、`.agents/skills/cognitive-model-calibration/` にケースとして保存し、次回以降に参照する。
- 数字、数式、ログ、ファイル差分などの物差しが使える場合は、できるだけ使う。
- 関係は一方向で決めつけず、双方向で見る。例: `A が B に影響する` と `B から見ると A は何を意味するか`。
- 推論中は、いま使っている情報に過不足がないか、要素選びを間違えていないかを都度見直す。
- 出力やフィードバックがズレた場合は、一度止めて、推測、見直し案、修正したい方向を短く報告し、確認をもらってから進める。

## 関係の見分け方

- `上位 / 下位`: A が B の意味、範囲、目的を決めるなら A が上位。B が A の具体例、部品、手段なら B が下位。
- `支配 / 制約`: A が変わると B が強く変わる、または B の可能範囲を狭めるなら A は B を支配・制約している。
- `対等`: A と B が同じ粒度で、どちらも相手の意味や範囲を決めないなら対等として扱う。
- `相互影響`: A も B に影響し、B も A に影響するなら、片方向にせず `A -> B` と `B -> A` の両方を書く。
- 迷う場合は仮置きでよい。例: `A は B を制約しているかもしれない` と書き、作業中に見直す。
- 関係を見るときは、`どちらが目的を決めるか`、`どちらが範囲を狭めるか`、`どちらが具体例か`、`同じ粒度か` を順に確認する。
