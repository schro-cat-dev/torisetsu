# 2026-08-27 TODO UI フィードバックケース

## ユーザーフィードバック

```text
2 / 2 件
新規作成
この部分が新規作成ボタン押したらurlはnewに移るけど何も変わらないのと、
あとは
Quality Harness

TODO管理 v0.8.0
でQuality Harnessは絶対いらないしデザインを損なってると思う

あと、実際のアイテムの詳細ボタン押すと画面の右上に詳細画面が表示されるけど、
UXとしてかなり悪いなんでここに出てくるの？しかも閉じるボタンそこまでカーソル合わせて押さないとダメなんだってなる
しかもその詳細が表示されてるアイテムに説明が表示されてないのにリストの方には薄い文字で詳細が書かれてる
```

## 変換したチェック項目

| 種類 | 変更前 | 困ること | 変更後 |
|---|---|---|---|
| ルート | `/todos/new` でも見た目がほぼ同じ | 押した結果が分からない | `/todos/new` で作成フォームを表示し、通常一覧とは差を出す |
| ノイズ | `Quality Harness` と version をヘッダー表示 | 利用者のTODO管理に関係ない | 画面から消し、成果物情報はdocsで管理する |
| 配置 | 詳細が右上パネルに出る | どのTODOの詳細か分かりにくい。閉じる操作が遠い | 詳細は対象カード内の行内トグルで表示する |
| 情報配置 | 一覧に説明、詳細にも説明 | 一覧と詳細の役割が曖昧 | 一覧は要約、詳細トグル内で追加情報を確認する |
| フォーム | 必須/任意と文字数がデータ化されていない | 表示、validation、仕様がズレやすい | field meta から必須/任意、文字数、validationをそろえる |
| 分類 | 固定enumだけで扱っている | ユーザーが分類を追加できず、TODOの分け方が硬い | `categories.json` を正本にして、TODOは `categoryId` を持つ |
| 分類保護 | デフォルト分類の保護情報がない | 初期分類を後で誤って変更・削除しやすい | デフォルト分類は `locked: true` にする |
| 再読み込み | 通常UIに `再読み込み` が出ている | エラー時retryがあるため、通常画面ではノイズになりやすい | 通常UIから削り、失敗時の `もう一度試す` に寄せる |

## 次回の動き

- UIフィードバックを受けたら、まず `提供価値 / ルート / 配置 / 責務 / 入力項目 / クリック範囲 / 重なり / ノイズ` に分ける。
- すぐ実装できるものは直す。
- 判断が必要なものは、`必要 / おすすめ / 今はしない` に分ける。
- 機械で見られるものはE2Eや静的checkへ落とす。

## 機械確認に落とせる例

- `/todos/new` で `新しいTODO` が表示される。
- `/todos` で作成フォームが常時表示されない。
- 画面に `Quality Harness` が表示されない。
- `必須` が2件、`任意` が3件表示される。
- ブラウザタイトルが `TODO管理` になっている。
- `0 / 80文字`、`0 / 400文字` が表示される。
- カード本文クリックで詳細が行内表示される。
- もう一度カード本文をクリックすると詳細が閉じる。
- 右側に `詳細 / 閉じる` ボタンは表示されない。
- 編集クリック後、編集モーダルだけが表示される。
- 編集後、一覧の表示が更新される。
- 分類は `categories.json` から表示される。
- デフォルト分類は `locked: true` で保存される。
- 新しい分類を追加し、その分類をTODOに紐づけられる。
