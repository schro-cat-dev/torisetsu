## 次回からの反映

- `契約`、`機械で守る`、`フィルタする`、`高精度`、`安全` のような抽象語を使ったら、必ず値や例に落とす。
- 設計やtipsでは、`何をするか` だけでなく `どの値ならOKか`、`NG例 / OK例`、`入力例 / 出力例` のどれかを添える。
- コードレビューエージェントの例なら、`policy_id: "ARCH-001"`、`confidence < 0.75 は投稿しない`、`max_comments: 10`、`reviews: []` のような設定値まで出す。

- 他回答が一部を具体化していても、周辺に抜けた実装項目があれば補完する。例: schema だけでなく、diff行マッピング、重複排除、severity判定、GitHub投稿payload、評価データ、失敗時リトライも見る。
