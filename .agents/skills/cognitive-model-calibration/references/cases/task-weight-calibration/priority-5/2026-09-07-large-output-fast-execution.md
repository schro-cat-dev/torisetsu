# 大きい成果物でも速く完成させる

## 視点

実行速度と成果物品質 / 優先度: 5

## 状況

AIが短い期限を、小さな成果物だけを作る指示として解釈しかけた。ユーザーは、成果物の規模を落とすのではなく、AIの並列性と実行速度を使って、設計、実装、検証まで短時間で完成させることを求めていた。

## AIが迷った点

- 短時間と大きな成果物を両立する際、どこを削るか。
- 作業量の見積もりを、人間が逐次作業する速度へ寄せすぎていた。

## ユーザーの返答

- 小さな成果物だけが30分から1時間で終わるという意味ではない。
- 重要な別作業へ集中するため、任せた範囲は品質を妥協せず完成させてほしい。
- ユーザーを上級技術判断者として扱い、不要な基礎説明や確認で止めない。

## 次回の動き

- 時間制約を成果物縮小へ直結させず、決まっている作業はまとめて実行する。
- 削る対象は品質条件ではなく、重複説明、不要な確認、未使用の将来案とする。
- 完成条件を設計、実装、test、証跡まで置き、各工程を止めずに通す。
