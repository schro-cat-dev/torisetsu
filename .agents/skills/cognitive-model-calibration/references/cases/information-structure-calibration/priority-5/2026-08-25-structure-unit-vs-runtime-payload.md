## 視点

- 視点: 認知モデル差分の再発防止
- 優先度: 5
- おすすめ度: 5

## ズレた点

AIは `構造化した単位で運び、扱う` という表現を、概念整理として書いたつもりだった。

ただし、ユーザーの意図では、構造単位で `関連付けて把握する` ことが重要であり、アプリやシステム内部の処理フローで、目的、分類、責務、依存関係、評価軸、重要度、影響度を常に一つのpayloadのように運搬する意味ではない。

より根本では、AIが `人間がその概念をどういう意味で使っているか` と `実装上それをどう表現するか` を分けきれていなかった。

## 修正後の表現

```text
情報は個別の点だけで扱わず、構造化した単位として関連付けて把握する。構造単位では、目的、分類、責務、依存関係、評価軸、重要度、影響度を整理する。ただし、アプリやシステム内部の処理フローで、それらを常に一つの塊として運搬するという意味ではない。概念と関係性を明示しておくことで、後から別用途へ移す、比較する、拡張する、別の仕組みに接続する、といった選択肢が増える。
```

## 次回ルール

- `構造単位で扱う` と書くときは、次を分ける。
  - 概念整理: 関係性を把握するために、目的、分類、責務、依存関係、評価軸などを結びつける。
  - 実行時運搬: アプリやシステムの処理フローでは、責務境界に合わせて必要なデータだけを渡す。
- 概念を実装へ落とす前に、次の2つを分ける。
  - 人間側の意味: ユーザーがその概念を何のために使っているか。
  - 実装上の表現: その意味を state、API request、DB record、log、document などのどこへ、どの粒度で載せるか。
- `運ぶ`、`運搬する`、`一つの単位で扱う` という表現は誤解が出やすい。実装やデータフローの話では、payload、state、API request、DB record などの責務境界を明示する。
- 概念整理の話では、`関連付けて把握する`、`関係性を明示する`、`後から比較・拡張できるようにする` を使う。
