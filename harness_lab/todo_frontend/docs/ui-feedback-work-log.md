## 失敗から分かったこと

- `check:api-flow` は sandbox 内のローカルAPI起動で `listen EPERM` になったため、権限付き実行が必要だった。
- Playwright は既存サーバを再利用すると古いAPIを見てしまうため、専用ポートと `PLAYWRIGHT_REUSE_EXISTING_SERVER=0` が必要だった。
- 専用Webポートを使う場合、API側のCORS許可元も `TODO_WEB_ORIGIN` で合わせる必要があった。
- E2Eの `追加`、`分類`、`完了` は部分一致で衝突したため、対象を絞る必要があった。
- checkbox用の `label` がタイトルを包むと、タイトルクリックだけで `done` になり、通常一覧から消える。
- modalを作る時は、重なり順だけでなく、白い本体背景があるかも確認する必要がある。
- カード全体クリックを入れる場合は、checkbox、リンク、削除ボタンの `stopPropagation` を確認する。

## 次回の分割案

1. UI表示だけ直す。
2. データ型とAPIを直す。
3. E2Eを直す。
4. checklistと台帳を直す。
5. 最後に `npm run check` を通す。

この順番なら、壊れた場所を小さく見つけやすい。
