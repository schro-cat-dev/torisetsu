## 2. 追加した確認条件

- `/todos/new` で `新しいTODO` がモーダル表示される。
- `/todos` では作成フォームが常時表示されない。
- 画面とブラウザタイトルに `Quality Harness` が表示されない。
- `必須` が2件、`任意` が3件表示される。
- タイトルは `0 / 80文字`、説明は `0 / 400文字` が表示される。
- 入力後に文字数が更新される。
- 分類は `すべて / プライベート / 仕事 / 日常` を横並びで持つ。
- 新しい分類を追加し、作成するTODOに紐づけられる。
- 新しい分類には色を選べる。
- 分類フィルターで作成したTODOに絞り込める。
- 通常UIに `再読み込み` ボタンを表示しない。
- 詳細はカード本文クリックで行内表示される。
- もう一度カード本文をクリックすると詳細が閉じる。
- 右側に `詳細 / 閉じる` ボタンは表示されない。
- 編集クリック後、編集フォームがモーダル表示される。
- タイトル付近をクリックしても、TODO行は消えない。
- 詳細トグルと編集モーダルは同時に主役化しない。
- 編集後、変更後のタイトルと説明が表示される。
- 完了クリック後、通常一覧から消え、完了済み画面に表示される。
- 完了済み画面では `completedAt` の新しい順に並ぶ。

## 3. まだ判断が必要なこと

| 項目 | 優先度 | おすすめ度 | 理由 |
|---|---:|---:|---|
| 削除確認を `window.confirm` のままにするか | 4 | 4 | 危険操作だが、今は小さいTODOアプリなので重いmodalはまだ過剰かもしれない |
| URL query に検索/絞り込み/並び替えを持たせるか | 3 | 3 | 共有URLが必要なら有効。ローカル実験では必須ではない |
| API失敗時のretryやmock状態を増やすか | 4 | 4 | 失敗時UXを見るには必要。今は実API正常系が中心 |
| Firefox/Safari/mobile確認を追加するか | 3 | 4 | ブラウザ差分確認には有効。現時点ではChromium中心でよい |
