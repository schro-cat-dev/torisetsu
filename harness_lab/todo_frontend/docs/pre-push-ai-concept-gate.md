# pre-push/PR AI概念境界ゲート

## 1. 結論

push や PR の前に、AIが差分を見て `OK / NG` を判断する運用ゲートを置く。

実際にAIへ渡す確認表は `pre-push-ai-check-cheatsheet.md` に分ける。

このゲートで見る中心は、通常のテストでは拾いにくい次のズレ。

- 人間の語感、違和感、概念上のズレを、機械判定できる条件と混ぜていないか。
- Harnessで直接見られないものを、見られるものとして扱っていないか。
- 機械確認したい場合に、観察メモから判定条件へ変換できているか。

これは LLM が活きる用途の一つとして扱う。文字列一致や型検査ではなく、概念の層、文脈、言い換え、混ざり方を読むため。

## 2. 対象

対象:

- README、AGENTS、docs、spec、checklist、Issueコメント、PR説明。
- AIレビュー結果や、AIが出したOK/NG判断。
- Harnessの観点、評価軸、判定条件、残リスクの説明。

対象外:

- TypeScript型、unit、API flow、buildなど、既に機械で確認しているもの。
- 実AI API呼び出し。
- GitHub PRへの自動投稿。

## 3. 入力

AIは次を見て判断する。

| 入力 | 使い方 |
|---|---|
| ユーザー依頼 | 何を求められているかを見る |
| `git diff` | 何を変えたかを見る |
| 関連docs | 既存ルールと矛盾していないかを見る |
| 実行結果 | 機械チェックのOK/NGを見る |
| 未解決メモ | 人間判断が必要なものを分ける |
| AIチェックチートシート | AIの見る順番と出力型を固定する |

## 4. 判定項目

| 観点 | OK | NG |
|---|---|---|
| 概念境界 | 人間の違和感と機械判定を分けている | 違和感をHarnessが直接拾う前提にしている |
| 変換 | Harness化する前に判定条件へ変換している | 観察メモをそのままcheck項目にしている |
| 証跡 | どのdiff、どのcheck結果を見たか言える | 何を見てOKにしたか不明 |
| スコープ | push/PR対象の差分だけを見ている | 別スコープへ勝手に広げている |
| 次の行動 | NG時に直す対象と方法がある | NGなのにそのまま進める |

## 5. OK/NGの決め方

OK:

- 通常checkが通っている。
- 人間の違和感、観察、解釈、機械判定が分かれている。
- Harness化するものは、機械で見られる条件になっている。
- 残リスクがある場合でも、push/PRを止めるものではないと説明できる。

NG:

- Harnessが直接見られないものを、見られるものとして書いている。
- 人間の語感や概念上のズレを、数値や自動検出結果のように扱っている。
- 判断根拠がなく、AIが雰囲気でOKにしている。
- ユーザー指示、既存ルール、合流条件と矛盾している。

## 6. 報告フォーマット

```text
AI pre-push gate: OK / NG

対象:
- <今回の差分>

見たもの:
- <git diff / docs / 実行結果>

判断:
- <なぜOKまたはNGか>

NGの場合:
- 問題: <何が混ざっているか>
- 修正: <どう分けるか>
- 次の行動: <直してから再確認 / ユーザー判断へパス>
```

## 7. 今回の具体例

NG:

```text
人間の違和感5件のうちHarnessで拾えたのは1件だった。
```

理由:

- 人間の語感や概念上の違和感を、Harnessが直接検出できるものとして扱っている。
- 別の概念空間を混ぜている。

OK:

```text
ユーザーは `UIコンポーネントごとの必要性説明不足` に違和感を持った。
これはHarnessが直接拾う対象ではない。
Harness化する場合は、`各UIコンポーネントに目的、利用者への効果、必要性、完了条件が書かれているか` のような判定条件へ変換してから扱う。
```

理由:

- 人間の観察と機械判定を分けている。
- Harness対象にする条件が具体化されている。

## 8. 今後の改善

- AIのOK/NG判断も、必要になったらJSON化する。
- 例: `status`, `checked_files`, `concept_boundary_findings`, `blocking_reasons`, `next_action`。
- 最初は手動のAIゲートで十分。PR自動コメントやCI連携は、必要になってから足す。
